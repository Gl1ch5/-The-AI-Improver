# AI Improver

Серверный прокси, который **незаметно улучшает ответы любой нейросети**. Снаружи это обычный OpenAI-совместимый API (`/v1/chat/completions`, стриминг, tools). Внутри перед каждым запросом маленькая быстрая модель без размышлений классифицирует задачу, пишет короткую критику и подбирает рабочие инструкции из встроенной библиотеки. Всё это тихо попадает в системный контекст основной модели.

```
клиент ──► AI Improver ──► классификатор (быстрая модель, ~150 токенов контекста)
             │                 └─► {инструкции: [web-design], критика: "...", сложность}
             └─► основная модель (системный промпт + инструкции + критика) ──► стрим клиенту
```

## Что внутри

- **OpenAI-совместимый API**: `POST /v1/chat/completions` (stream и без), `GET /v1/models`. Подходит любой клиент OpenAI SDK, Cursor, Continue, Open WebUI и т. п.
- **Классификатор-критик**: видит только последний запрос (обрезанный до ~1200 символов) и одну строку контекста, отвечает компактным JSON. На приветствия и «спасибо» вызова нет. Повторные запросы берутся из кэша. Если модель недоступна или не уложилась в таймаут, работают локальные эвристики по ключевым словам, и запрос не ломается.
- **Библиотека из 118 инструкций** в `server/library/*.json`, по 6 категориям:
  - поведение: краткость, без подхалимства, честность, форматирование, ролевые игры, ELI5;
  - тексты: хуманайзер по [blader/humanizer](https://github.com/blader/humanizer) и Wikipedia «Signs of AI writing», «общайся как человек», инфостиль, копирайтинг, сценарии;
  - дизайн: `frontend-taste` по [taste-skill](https://github.com/Leonxlnx/taste-skill), лендинги, дашборды, типографика, доступность;
  - код: агентная разработка и исправление багов в стиле SWE-bench, ревью, языки, regex, bash;
  - рассуждения: приёмы, повышающие точность на MATH/AIME, GPQA, IFEval и SimpleQA;
  - сферы: маркетинг, финансы, право, здоровье, обучение, Telegram-боты и другое.

  Инструкции — короткие повелительные заметки по 100–250 токенов. Их можно редактировать, отключать и добавлять свои. Классификатору уходит компактный каталог из одних id, около 600 токенов. Отредактированные инструкции не перезаписываются при обновлениях.
- **«Липкие» стили**: если пользователь один раз попросил «общайся как человек», «отвечай коротко» или начал ролевую игру, нужная инструкция действует до конца диалога. Проверка локальная, без токенов.
- **Режимы улучшения** для каждой модели:
  - `подсказки`: инструкции и критика добавляются до отправки запроса. Минимальная задержка.
  - `советник`: для сложных задач основная модель получает скрытый инструмент `quality_review`. Перед ответом она отправляет туда свой план, быстрая модель его критикует, и генерация продолжается с учётом критики. Клиент этого вызова не видит, даже при стриминге.
  - `подсказки + советник`: оба механизма сразу.
- **Виртуальные модели**: любое имя для клиентов, любая целевая модель у любого провайдера, свой системный промпт и доп. параметры.
- **Веб-панель**: обзор и статистика (токены классификатора, попадания в кэш, задержка), модели, классификатор и советник с тестовой проверкой, провайдеры, библиотека, песочница со стримингом и показом того, что было подмешано, журнал запросов.

## Запуск

Нужен Node.js 20+. Зависимостей нет.

```bash
cp .env.example .env    # задайте ADMIN_PASSWORD
node --env-file=.env server/index.js
# открыть http://localhost:3210
```

Docker:

```bash
docker build -t ai-improver .
docker run -d -p 3210:3210 -v $PWD/data:/app/data -e ADMIN_PASSWORD=secret ai-improver
```

Systemd на сервере: `sudo bash deploy/install.sh`, затем поправить `/opt/ai-improver/.env`. Пример nginx с TLS лежит в `deploy/nginx.conf`. Для стриминга обязательно `proxy_buffering off`.

## Использование

```python
from openai import OpenAI
client = OpenAI(base_url="http://your-server:3210/v1", api_key="sk-imp-...")
stream = client.chat.completions.create(
    model="gemini-improved",
    messages=[{"role": "user", "content": "Сделай лендинг для кофейни"}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

## Экономия токенов

- Классификатор получает только последний запрос, а не всю историю. Обычно это 300–500 токенов на входе и 30–60 на выходе.
- Тривиальные сообщения обрабатываются без вызова модели.
- Результаты кэшируются по хэшу (TTL настраивается).
- В запрос попадают максимум 2 инструкции, только релевантные.
- Советник включается только для запросов, которые классификатор пометил как `complex`.
- Для моделей с размышлениями в «Доп. параметрах» классификатора можно их отключить: `{"reasoning_effort":"minimal"}`, `{"enable_thinking":false}` и т. п.
